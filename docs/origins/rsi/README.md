# Embodied RSI

连接 [EmbodiedJev](https://github.com/FBddcz/embodied-jev) 的 MuJoCo 机械臂仿真与 [RSI-Jev](https://github.com/Shanghua-Gao/RSI-Jev) 的决策模型。

当前实验只做一项任务：**把物体放进盘子**。旧轨迹、数据集、指标、微调检查点、部署版本和旧结果报告已清空。原始 RSI 预训练权重作为新实验起点。

**自主尝试 → 物理判定成功 → 收集成功动作 → 训练 → 新场景配对评测 → 达标更新 → 最终同场景审计。**

## 2026-10-08 早期协议测试

冷启动实测：原始 RSI 在 12 次随机探索中成功 1 次，另 11 次失败。探索完成率为 8.3%，这不是确定性独立评测成绩。没有使用教师示范初始化。

| 阶段 | 本次预算 |
|---|---|
| 任务与控制 | 搬运入盘，最多 20 个技能动作 |
| 初态 | 源物体位置在中心附近 ±2.5cm 随机；目标盘位置固定 |
| 学习轮数 | 3 轮 |
| 每轮自主采集 | 30 局；可继续利用前面实际成功轨迹 |
| 每轮训练 | 100 次 RSI 决策头更新，冻结文本塔 |
| 开发选模 | 10 个独立完整任务，按完成率选择检查点 |
| 每轮发布评测 | 90 对新场景，候选与当前版本使用同初态 |
| 最终统一审计 | 本次快速验证为 30 个保留场景；正式默认 90 个 |

所有轮次结束后才揭示最终审计集。分别画候选曲线与实际发布版本曲线；下降、持平和未发布都保留。**不保证、不强制成功率逐轮上升。** 单次通过发布门槛也不能证明整个学习曲线严格上升。

## 安装与使用

Python 3.11+、Git、uv；前端不需要 Node.js 或外部 CDN。

```bash
git clone https://github.com/gaohuan2020/embodied-rsi.git
cd embodied-rsi
python3 scripts/bootstrap.py --rsi
.venv/bin/embodied-rsi dashboard --port 8091 --rsi-python "$PWD/.venv-rsi/bin/python"
```

[机械臂模拟](http://127.0.0.1:8091/simulation) · [训练与测试报表](http://127.0.0.1:8091/training)

macOS 使用 CGL 渲染，Linux 默认使用 EGL；显式设置的 `MUJOCO_GL` 优先。
RSI 训练和推理自动选择 CUDA、Apple Silicon MPS 或 CPU，也可通过
`EMBODIED_RSI_DEVICE=mps`（或 `cuda`、`cpu`）固定设备。两端均保留 FP32。
多轮实验在每轮结束后释放临时模型引用与 GPU 缓存，避免下一轮加载时累积占用。
原文成绩来自 CUDA，其他设备的完成率和耗时须以实际运行结果为准。

完整复现脚本会分别保存新采集、一轮闭环验证、当前协议三轮研究、早期九技能三轮研究、
代码策略对照和推理一致性检查。历史自主轨迹不在 Git 中，因此脚本重新采集原始模型的
成功尝试，不能保证得到历史报告的逐项数值。每项实验使用独立目录，失败日志也会保留：

```bash
.venv-rsi/bin/python scripts/reproduce.py run --output artifacts/reproduction-new
```

可用 `--stages collect verification` 等参数分阶段运行；已完成的阶段不会重跑。
`reproduction.json` 记录实际设备、依赖版本、命令、日志路径和各阶段状态。

训练页可启动「搬运入盘验证」。命令行等价运行：

```bash
.venv-rsi/bin/embodied-rsi transfer-study --rounds 3 --explore-episodes 30 \
  --steps 100 --episodes 90 --audit-episodes 30 --max-steps 20
```

需要新 `artifacts/` 或用全新目录 `--artifacts artifacts-transfer-new`；已有部署时研究命令拒绝复用旧基线。默认正式审计预算为 90。

继续单任务自动学习：

```bash
.venv-rsi/bin/embodied-rsi self-improve --tasks transfer --rounds 3 \
  --explore-episodes 60 --episodes 90 --steps 100
```

模拟页默认仅搬运入盘，支持连续执行、暂停、单步、停止、相机和回放；达到新增 30 局且至少 5 局成功后可自动训练。目标位置随机化暂不进入本轮实验，后续单独测试泛化分布。

## 训练与发布

模型请求选择九种技能，程序负责航点／IK，MuJoCo 执行物理并独立判定位置、稳定支撑、释放与撤离。模型输入为当前结构化状态；画面来自 MuJoCo 渲染。

失败记录用于调整探索，发布评测使用原模型确定性决策。只回放模型实际成功轨迹中的执行动作；过滤被拒、空抓、失抓和未持物搬运动作。loss 用于训练诊断，完整任务完成率决定保存哪一步。冻结塔缓存严格保留候选顺序；训练与线上统一 FP32，并验证预测一致。

新的 RSI 冷启动默认启用分阶段提示和严格抓取，不再要求手动设置环境变量。训练检查点保存这些设置，开发验证、重新加载和网页仿真均沿用同一输入协议；已有检查点的设置优先。旧检查点可从保留的训练数据恢复这些设置；移动旧检查点时应同时保留其 `meta.json` 中指向的数据集。此前仅靠环境变量启用设置，重启后可能丢失，已复现同一训练模型在相同三个场景由 3/3 成功降至 0/3；这项小样本检查用于定位协议缺陷，不替代独立发布评测。需要复现早期九技能实验时，可显式设置 `EMBODIED_RSI_STAGED_PROMPTS=0 EMBODIED_RSI_STRICT_GRASP=0`。

自我改进的发布评测强制重载已经保存的检查点，配对场景同时校验初态、输入协议与物理成功判定。历史自主采集不受网页最近 200 条作业的显示上限影响，同一轨迹重复导入只计一次；开发场景不得出现在回放训练数据中。复用历史数据而没有新增采集时，成功率显示为缺失值。

完整闭环验证脚本为 `scripts/verify_learning_loop.py`：在全新 `--artifacts` 目录导入指定 `--episodes-file` 中原始模型的真实自主尝试，从本地 `--baseline` 权重训练，运行 90 对发布评测，通过后自动发布，再清除环境变量并通过运行时重新加载执行 30 局新场景。脚本核对决策头文件确实变化；结果保存在 `verification.json`，逐局记录保存在对应实验目录。验证使用历史采集，只能证明该任务的一轮闭环，不能据此宣称后续各轮必然提升。

2026-10-15 已完成这项独立验证：复用原始模型 23 次自主尝试中的 9 条成功轨迹，共 101 个动作样本；训练 100 次，选中第 50 步，开发完成率由 0/10 提高到 6/10。重载后的 90 对发布评测为原始模型 0/90、候选 74/90（82.2%），碰撞、失抓与拒绝均为 0，通过门槛后实际发布。移除环境变量后，经部署运行时重载，另 30 个新场景完成 24/30（80%）。[完整验证数值](docs/results/learning-loop-verification.json)。结果只覆盖搬运入盘的一轮训练，验证目录为 `artifacts/flow-verification-20261015`。

2026-10-19 在 Apple M1 Pro（16 核 GPU、16GB 统一内存）上以 MPS / FP32 重新完成了这一轮闭环，实验未使用远程 GPU。重新采集的 23 次尝试得到 9 条成功轨迹、101 个动作样本；100 次更新后选中第 50 步，发布评测为 **74/90 对 0/90**，运行时重新加载后为 **24/30**。这些完成数与历史记录一致，但训练后的决策头字节不同；另已核对冻结塔未变化、12 个决策头张量确实变化。环境、模型版本、逐项结果及限制见 [Mac 单轮复现记录](docs/results/macos-learning-loop-verification.json)。

2026-10-20 又在独立目录完成当前分阶段提示／严格抓取协议的 MPS 三轮研究：每轮 30 局自主采集、100 次更新、90 对发布评测，最后统一审计 30 个保留场景；目标盘固定、每局最多 20 个技能动作。这与上面的早期九技能研究属于不同协议，结果分别保存。

| 版本 | 本轮采集成功 | 发布评测：候选 / 当前 | 同场景最终审计 | 发布决定 |
|---|---|---|---|---|
| V0 | — | — | 0/30 | 原始模型 |
| V1 | 10/30 | 72/90 / 0/90 | 19/30 | 发布 |
| V2 | 13/30 | 85/90 / 75/90 | 28/30 | 发布 |
| V3 | 21/30 | 90/90 / 87/90 | 30/30 | 保留 V2 |

V3 的发布评测提升为 3.3 个百分点，95% 区间为 [0, 7.8] 个百分点，未达到发布门槛；最终审计不参与发布决定。因此，这 30 个场景上的候选曲线逐轮上升，实际部署曲线在第 3 轮持平，实际更新次数为 2。完整预算、开发选模、模型哈希及限制见 [Mac 当前协议三轮结果](docs/results/macos-transfer-study.json)。

同日也在 MPS 上完成了早期九技能协议的独立复现：冷启动为 **0/12**，三轮自主采集分别为 **3/30、5/30、1/30**，累计 9 条成功轨迹、83 个过滤后的动作样本。每轮均实际完成 100 次更新，分别选中第 0、100、0 步；发布评测候选为 **0/90、2/90、0/90**，对照均为 0/90。第 2 轮提升区间为 [0, 5.6] 个百分点，并有 18 次失抓和 2 次拒绝，三轮均未发布。V0～V3 在最终 30 个保留场景中均为 **0/30**。新采集数据与历史记录不同，因此逐项数值不完全相同；未观察到可靠提升的结论一致。旧协议的成功判定也与严格抓取不同，两类成绩分别报告。完整记录见 [Mac 早期协议三轮结果](docs/results/macos-legacy-transfer-study.json)。

四种策略、两类场景各 90 局的 **720 局代码策略对照**也已完成：正常／空抓故障场景中，代码策略为 **90/90、90/90**，失败即停止对照为 **90/90、0/90**，RSI 为 **73/90、71/90**，混合策略为 **90/90、90/90**。本次使用事先选定的单轮复现检查点，历史对照权重不可用；结果不触发部署。数值、耗时以及严格释放失败与汇总风险计数的区别见 [代码策略实验](docs/CODE_POLICY.md) 和 [Mac 策略对照记录](docs/results/macos-code-policy-study.json)。

最终网页检查使用已发布 V2、固定目标、场景 `1020000`、最多 20 步，关闭连续采集、探索和自动训练。真实模型以 9 个动作完成任务，保留 231 帧回放；单步、继续、相机切换和回放均通过，浏览器无脚本错误。初态、输入协议和动作序列与 V2 的原始审计记录一致。这是既有审计场景的运行一致性检查，不计作新的独立泛化成绩；记录位于本地 `artifacts/reproduction-20261019/browser/current-rsi-controls.json`。

| 发布门槛 | 要求 |
|---|---|
| 独立配对 | 当前仅 transfer，至少 90 对 |
| 完成率提升 | ≥5 个百分点 |
| 95% 配对 bootstrap 区间 | 提升下界 >0 |
| 任务与风险 | 无超限任务退化，碰撞／失抓／拒绝不增加 |

通过才自动部署，下一局读取新模型，运行中的一局固定版本。报告与注册表写明验证过的任务范围；单任务成绩不能宣称覆盖堆叠或越障。

数据、模型、作业和 SQLite 存储在忽略的 `artifacts/`。冻结协议为 `runs/study-*/protocol.json`，每轮配对结果为 `runs/evaluate-*/report.json`，最终结果为 `study-latest.json`。本地界面限制 Host 与跨 Origin 写请求，远程可用 SSH 转发。当前部署目标为仿真服务。
